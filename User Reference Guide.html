    User Reference Guide

    A radio for the corner of your computer desktop. It plays internet streams from stations you choose, on a schedule if you want one, and it looks like a radio rather than a browser tab.

    To find something in here, use the search box in the bar at the top: four letters or more, matched against everything below and not only the headings. It lists the sections your word appears in, with a count, and marks every one of them on the page; the ✕ clears the search and the marks with it. Once you are well down the page an arrow appears at the bottom right to put you back at the top.

    Deskside Radio is webpage-based application. There is nothing to install, no account and no server. Nothing about you is sent anywhere; the two things that do leave your machine are the stations you play and, on each launch, a request to Google Fonts for the typefaces. Both are listed under Your data.

    01In a hurry to get started?

    1. Double-click Win-Install-or-Update-Deskside-Radio.cmd.
    2. Press play.

    That’s all — it installs the radio, puts a shortcut on your Desktop and opens it.

    If there is no shortcut on your Desktop yet it asks which browser to open in: C for Chrome (or Edge, where Chrome is not installed), E for Edge, F for Firefox. Pressing Enter takes Chrome. If shortcuts are already there it asks nothing and repoints the ones you have.

    It also tells you which version it is putting in, and which one that replaces.

    If you are reading this inside a folder you unzipped yourself, double-click Win - Create Desktop Shortcut (Chrome).cmd instead and it works the same way from where it stands.

    Everything below is detail you can come back for. On a Mac or on Linux, see Choosing a browser.

    02What is in this folder

    index.html
    The radio itself. Everything is in here.
    Win-Install-or-Update-Deskside-Radio.cmd
    Installs the radio, and updates it later. The same file does both. You should not need to run it for an update — the radio does that by itself — but running it takes one straight away.
    Win - Create Desktop Shortcut (Chrome).cmd
    Makes the Desktop shortcut on its own, for a folder you unzipped by hand.
    Win - Create Desktop Shortcut (Edge).cmd
    Win - Create Desktop Shortcut (Firefox).cmd
    The same, pinned to one browser on purpose.
    Win - Start with Windows (On-Off).cmd
    Opens the radio when you sign in. It is the switch as well as the installer: run it and it tells you whether it is on, and offers to turn it off again or aim it at this folder.
    Win - Deskside Radio Protocol.vbs
    Not one to double-click. It is what the Start when you sign in control in Settings reaches when you use it: Windows hands it the request and it runs the script above. It understands two words and ignores everything else.
    Win - Automatic Updates.cmd
    Controls whether the radio updates itself. Nothing is installed or removed either way: it writes, or deletes, one small file in the app folder that the launcher looks for before it checks for a newer version. Run it with off to stop the updating; run it with no argument to start it again.
    Win - Uninstall Deskside Radio.cmd
    Takes it off again: this folder, the folder it sits in once nothing is left in it, and every shortcut it put on the Desktop, in Startup and in the Start menu. Your stations and settings are kept unless you say otherwise — it asks about those separately, because that is the one part reinstalling cannot bring back.
    Linux - Create Desktop Shortcut.sh
    Both of those, for Linux. Add --autostart for sign-in.
    User Reference Guide.html
    This file — a user guide style description of the Deskside Radio app, its features and functions.

    The window

    The radio sizes its own window to the theme, and the themes are not the same height, so the window changes shape when you change theme. Where it sits is remembered and put back before the page is drawn.

    On Windows the window cannot be resized by hand. The Desktop shortcut and the Startup entry point at Win - Open Deskside Radio.cmd rather than at the browser: it starts the browser and then takes the window's resize grip and maximise box away. No dragging the edges, no double-clicking the title bar, no Win+Arrow snapping — while the radio stays free to size the window itself. It exits as soon as the window is locked, console minimised, and nothing is installed or left running. It will wait up to a minute for the window to appear: at sign-in nothing is warm, and the radio has been seen taking more than a minute to come up after a reboot on a machine where it opens instantly by hand. A folder without that file falls back to a shortcut aimed straight at the browser, and the window stays resizable.

    There is no way to do this from the page. No web API makes a window non-resizable and no browser switch does either, which is the only reason a launcher script exists.

    On macOS and Linux the window can still be resized, and a size you set by hand is not kept. The radio opens where you left it, at the size the theme wants.

    One position cannot be reproduced: hard into the top-left corner. Windows puts an invisible resize border outside a window's visible frame, so that corner is a negative coordinate, and a page is not allowed to place a window partly off the screen. It comes back inset by a few pixels.

    The mini radio

    The pushpin in the top bar opens a small strip that floats above every other window — station, what it is doing, play, volume, a meter and a clock — and tucks the radio’s own window out of sight behind it. The expand button on the strip puts the radio back, and so does Escape. The strip’s close button closes the radio altogether, which is why there is only one of them: Chrome’s own back-to-tab button is turned off, so one browser control means one thing.

    During a slot change the strip says what is about to happen and counts the last thirty seconds down — Schedule change in 30s, or Schedule play ends in 30s, or Schedule play ends, then freeplay in 30s — and its fader rides the handover fade exactly as the radio’s own does. Double-clicking the fader slides it back to 50.

    It is a picture-in-picture window, which is the only kind a browser will float above the others. So: Chrome, Edge, and Firefox 151 or newer. Safari has no such window and neither does any mobile browser, and there the pushpin is not shown at all rather than offered and broken.

    The window nothing can size

    A page cannot decide how big one of these windows is. Chrome ignores the size it is given — 440×150, 440×240 and 600×400 were each measured opening at 1119×700, which is simply its default for the display — and although the window can be resized afterwards, that needs a live user gesture, and the gesture that opened it was spent opening it.

    So on Windows the opener starts strip-fit.ps1 beside the radio. It is the only thing this project leaves running, and the only file in the folder nobody is meant to double-click. It waits for the floating window, sets it to the right size, takes its resize grip off so it cannot be dragged to some other shape, and does nothing else. It stops when the radio’s window goes, with a twelve-hour backstop in case it never sees that happen, and only one ever runs at a time. The uninstaller stops it before removing the folder.

    It picks the right window by asking Windows which one floats. Both windows answer to the same name — Windows captions a picture-in-picture window with the title of the page that opened it, not the title of the page inside it — and only the floating one carries the always-on-top flag.

    Everywhere else — macOS, Linux, and Firefox anywhere — nothing is started and nothing runs. The strip opens at whatever size the browser chose and says so, in the middle of itself: Click anywhere to shrink this window. One click sizes it. That prompt is keyed to the window actually being too big rather than to the platform, so it never appears on Windows, and it will stop appearing anywhere a browser begins honouring the size it is asked for.

    Tooltips

    The hints are the app’s own rather than the browser’s. A native one is a grey rectangle in a system font, after a delay nothing can change, and it says nothing at all if you reached the control with the keyboard — these appear on focus as well as on hover, after about four hundred milliseconds, and immediately after that while you are moving along a row. Escape dismisses one, and so does pressing the thing it belongs to.

    They wear the same neutral plate as the Settings drawer and the confirm boxes rather than changing with each of the eight faces — a face is for looking at, and a tooltip is for reading.

    One thing about them is genuinely worse than what they replace. A tooltip drawn by the page cannot leave the window; the browser’s own could, being drawn by the operating system outside the window entirely. So this one opens above the control where there is room, below where there is not, and beside it where there is room for neither — which in the mini radio, eighty-eight pixels tall, is the ordinary case.

    Getting the radio’s own window out of the way

    A page cannot minimise its own window — there is no API for it — and a browser will not let one be pushed off the edge of the screen either. So the radio’s window is shrunk to a placard and parked inside the floating strip’s own rectangle, where an always-on-top window covers it completely. That is as close to hidden as the web gets.

    It follows the strip if the strip is moved, and it does that on the strip’s clock rather than its own: a browser throttles the timers of a window it believes nobody can see, which is precisely what this window is. Run from its own window, the placard lagged far enough behind a drag to show at the edges.

    If the two ever do come apart, what shows is a small placard reading Floating, and clicking it brings the radio back.

    Settings → Service, holding Shift
    An Open app folder button appears beside Reset. It copies this folder's path and opens it for you. It cannot open File Explorer — a page is not allowed to start a program — so what opens is the browser's own listing, and the path is on your clipboard to paste wherever you want it.
    assets/
    Everything the radio needs and nobody opens — one favicon-*.ico per theme, for the shortcut, and LICENSE.txt. The root of this folder is only the things you double-click; this is where the rest of it went.
    assets/installed-here.txt
    The one file that says this folder is an installed copy rather than an archive somebody unzipped. It is written by the installer and is never inside the zip, which is the whole of what makes it mean anything — the two kinds of folder hold the same files otherwise, because the installer ships inside the zip. Without it the installer read “there is an index.html beside me” as “I am inside an install”, so unzipping the archive into Downloads and running the script in it installed the radio into Downloads, shortcuts and all. Delete it and nothing breaks; the next run in this folder simply installs to %LOCALAPPDATA%\DesksideRadio\app instead of updating here.

    Anything starting Win - is for Windows and anything starting Linux - is for Linux; on a Mac you make the shortcut from inside the radio instead, with the button in the top bar.

    Keep the files together in one folder. You can put that folder anywhere: Documents, OneDrive, a USB stick.

    03Getting started on Windows

    1. Download Win-Install-or-Update-Deskside-Radio.cmd from the releases page.

    2. Double-click it.

      Windows asks once whether to run a downloaded file — the script is plain text, so you can open it in Notepad and read it first. It then fetches the radio, unpacks it, puts Deskside Radio on your Desktop and opens it.

    That is the whole install. It goes in your own account’s program folder and needs no administrator, so nothing asks again — not now, and not when you update.

    If you already have the zip, it still works exactly as it did: unzip it anywhere and double-click Win - Create Desktop Shortcut (Chrome).cmd inside it.

    Use the helper, not the button

    The shortcut button inside the radio works, but a browser will not save a .url under its own name, so the file arrives called Deskside Radio.download and has to be renamed — and anything a browser downloads is tagged with where it came from. A page opened from your own disk has no address the tagger understands, so the file gets marked restricted and Windows asks “Do you want to open this file?” every single time.

    If you have already done it that way: right-click the file, Properties, tick Unblock, OK. That clears the mark for good.

    The helper has neither problem: it builds the shortcut on the spot instead of downloading it.

    The installer goes one better. Unzipping in Explorer puts that same mark on every script it extracts, which is why they ask before running; the installer unpacks them itself, and files that arrive that way carry no mark at all. The one question on the installer is the only one you ever answer.

    You can also just double-click index.html. It works, but you lose the two things the shortcut adds, described next.

    04Why use the shortcut

    The shortcut opens the radio in a browser window of its own, with no tabs, no address bar, and permission to start playing on its own.

    That second part matters. Browsers refuse to play sound until you click something, which is why a page opened normally always asks for one click first. The shortcut lifts that restriction for this window only, so Play on launch genuinely plays on launch.

    It uses Chrome, or Edge if Chrome is not installed. If you have neither, the shortcut still opens the radio in your normal browser, and you will just click once to start it.

    The window remembers where you put it. The first time, it sizes itself to the radio; after that it opens at the size and in the place you last closed it, including a size you set yourself by dragging the edge. Move it to the corner of the screen you want it in and it will be there tomorrow.

    To give the shortcut a different theme’s icon, run the script with that theme’s name:

    "Win - Create Desktop Shortcut (Chrome).cmd" console

    Settings shows you the exact line to use for whichever theme you are on.

    05That separate window

    Because the shortcut uses a browser profile of its own, it starts with no stations of yours in it. To carry your setup across:

    1. Open the radio the ordinary way and set it up how you like.
    2. Settings → Service → Export settings.
    3. Leave the downloaded deskside-radio-settings.js beside index.html.

    The next launch reads it, and so does every launch after that — but only when the file has changed since that browser last took it. So settings you change here and do not export are left alone, and exporting again is what tells every other shortcut to catch up. This is also how you set up a second machine.

    Export now saves the file into the app folder, beside index.html, rather than into your Downloads folder. That is the whole of step 3 done for you.

    06Choosing a browser

    Chrome and Edge behave identically here — Edge is built on the same engine, and everything in this guide was checked on both. If you are on a work machine with only Edge, nothing is missing.

    The Chrome script takes whichever of the two it finds, so most people need nothing else. The rest are for pinning to one browser on purpose:

    Win - Create Desktop Shortcut (Edge).cmd
    Makes Deskside Radio (Edge), pinned to Edge.
    Win - Create Desktop Shortcut (Firefox).cmd
    Makes Deskside Radio (Firefox). Firefox has no app-window mode, so this opens an ordinary window with a tab strip; press F11 for fullscreen. Autoplay there is a preference rather than a flag, so the script writes it into the profile it creates.
    Linux - Create Desktop Shortcut.sh

    Writes a .desktop entry. Add --autostart to start it at login, or --off to remove both. If it will not run:

    chmod +x "Linux - Create Desktop Shortcut.sh"

    Each shortcut has a browser profile of its own, and no profile can read another’s storage. The settings file beside index.html is the only thing all of them can see, so that is how a setup moves from one to another: Export settings in Settings → Service saves it there, and every shortcut reads it the next time it opens.

    It used to save into your Downloads folder, where nothing ever read it — which is why settings exported from Chrome never appeared in Edge. Each profile is now told to save into the app folder instead.

    The file is taken only when it has changed since that browser last took it. Whoever exported last wins.

    On a Mac

    Open index.html in Chrome, Edge or Safari. There is no script for it; the shortcut button next to Settings hands you a .fileloc file instead, which you drag from Downloads to the Desktop. If Finder refuses to open it, drag the address out of your browser’s address bar onto the Desktop — that always works.

    Safari plays everything here and handles HLS stations better than most, with two differences. It will not let a page opened from a file on disk remember anything, so stations and settings do not survive a reload; put the folder on a web server, or use Chrome or Edge, if that matters. And the window will not size or place itself, because that is the shortcut’s doing and the shortcut is a Chrome one.

    07Starting when you sign in

    Windows

    Double-click Win - Start with Windows (On-Off).cmd. It looks first and tells you where things stand, then asks. If it is off it offers to turn it on, which puts the same shortcut the Desktop one uses into your Startup folder. If it is already on it shows you which folder that entry opens and offers two keys: R to remove it, or P to point it at the folder you ran it from. Pressing Enter on its own changes nothing.

    That middle line is worth reading rather than skipping. A start-up entry made from a copy you unzipped somewhere temporary keeps opening that copy, and once the folder has gone what greets you at sign-in is the browser’s Your file couldn’t be accessed rather than a radio. If the folder it names is not the one you are in, press P.

    Nothing runs in the background. What this puts down is one file, in a folder you can open yourself: press Win + R and enter shell:startup.

    Or from Settings

    The same thing lives in Settings → Service → Start when you sign in, which shows you how it is set before you touch it.

    The first time, it is a button rather than a switch, and that is deliberate. Turning this on has to leave the page and ask Windows, and your browser asks you before it will let that happen — so a switch would move the moment you clicked it, while nothing had yet happened and the dialog was still open. A button has nothing to be wrong about. Once it has worked once it becomes an ordinary switch, because by then the asking is over.

    Press the button and your browser asks for permission. What it names is Windows Based Script Host rather than the radio — that is the part of Windows that runs the small script doing the work, and it is what the browser can see. Two steps, and the order matters: first tick Always allow, then click Open Microsoft Windows Based Script Host. Clicking Open closes the dialog, so a tick made afterwards is a tick made never, and you will be asked again every time. The radio keeps a browser profile of its own, so that tick applies to the radio and to nothing else you do.

    The line under the control says Asking Windows… while it waits, and it does wait: the shortcut can take a few seconds to appear after you answer the dialog. When it does, the line says so and the button becomes a switch.

    If it does keep asking, that is what happened. Tick the box the next time before you press the button.

    That question is worth a word, because it is the one surprising thing in the app. A page opened from a disk cannot put a file in your Startup folder — no browser allows it, and none should. So the control asks Windows to do it, through one small registered handler that accepts two words and ignores everything else. It is the only thing this app puts in the registry, it starts nothing by itself, and uninstalling takes it out again.

    For the radio to be playing when you sit down rather than just open, turn on Play on launch in Settings and choose a station, or set up a schedule.

    On a Mac or on Linux the control in Settings is not offered, and the reason is worth a line: it works by asking Windows to do something, and there is nothing equivalent to ask. What follows is the same job done by hand, once.

    macOS

    Use the shortcut button next to Settings to save a .fileloc file somewhere you will keep it, then open System Settings → General → Login Items, and add that file under Open at Login. It opens in your normal browser, so it will ask for one click before it plays — the trick the Windows shortcut uses to skip that click is a Chrome command line, and there is no equivalent to hand a login item.

    Linux

    Run Linux - Create Desktop Shortcut.sh in the app folder to get a launcher, then add that launcher to whatever your desktop calls its startup applications — GNOME and KDE both have one, and both read the same ~/.config/autostart folder if you would rather put the file there yourself.

    08What it does

    Stations

    Add any internet radio stream by name, frequency, colour and URL. Or search for one: Settings has a finder that looks up stations by city and name through a free public directory, shows the call sign and whether it is AM, FM or internet-only, and adds it in one click.

    Schedule

    Separate weekday and weekend time slots, each choosing a station. A slot hands over at its end time, so 07:00 to 10:00 runs until exactly 10:00 and the next slot picks up there. Slots may run past midnight, and a slot whose two times are the same plays all day. A slot can also force the volume, bass, treble or theme when it starts.

    Slots cannot be made to collide. What you have just set stays, and anything it runs into is cut back to make room; a slot with nothing left is removed. A line above the cards says what happened, with an Undo beside it that puts the whole change back. Adding a slot puts it where there is room and tells you when the day is full. Deleting a station the schedule uses asks whether its slots move to another station or go with it.

    A handover is not a cut. Through the last minute of a slot a hairline runs out along the bottom of the Schedule button, so you can see the change coming. Over the last five seconds the station fades down, and the one replacing it comes up over two seconds once it is playing. The volume control slides with it so you can watch the handover happen, but only the control moves: the number beside it stays where it is, and so does your setting.

    When the last slot of the day ends and nothing follows, the radio either keeps playing or turns itself off — your choice, set under the slots in Settings → Schedule, and set separately for weekdays and for the weekend. So the weekdays can stop at bedtime while the weekend carries on.

    Adding several slots in one go: Save keeps the drawer open on the Schedule tab with the slots folded shut, ready for the next one. Save on any other tab closes the drawer as usual.

    Play on launch

    Turn it on, pick a station, and the radio starts by itself when you open the shortcut. An active schedule slot wins over it.

    Sound

    Volume runs on a proper decibel scale, so the middle of the slider is the middle of the range rather than everything happening at the top. Bass and treble are kept per station, since a talk station and a music station rarely want the same settings. Double-click any slider to put it back to the middle.

    Meters

    A real VU meter with the ballistics of the mechanical article, fed from the actual audio rather than faked from the volume setting. Some streams refuse the access it needs, and the app says so rather than showing a meter that is guessing.

    VU means Volume Unit, and a VU meter measures the level of the programme, not how loudly you are listening to it. The needle therefore does not follow the volume fader — that is deliberate, and it is what the meters on a broadcast console or a tape deck do. Turn the volume down and the needle keeps swinging, because the station is still as loud as it was. The meters that do follow a volume knob are the power meters on a hi-fi receiver, which is a different instrument.

    The peak lamp. On the broadcast console theme one segment stays lit at the loudest thing the meter has seen — up instantly, held for a second and a half, then let down at a rate you can follow. A transient that clips is otherwise a single frame nobody sees. It sits on a whole segment rather than between two, which is why the bar is snapped to whole segments as well, and it goes out with the rest of the meter when the radio stops rather than holding the last loud moment of a station that is no longer playing.

    For the same reason the meter ignores the bass and treble controls: it is reading the station, not the room.

    It keeps playing

    Streams drop. The radio watches for silence and dropped connections and reconnects on its own, backing off from two seconds to thirty, and returns to whatever the schedule says or the last station that worked.

    Backup

    Settings → Service exports everything to one file and imports it back. Everything means everything: the stations, the schedule, whether the schedule is switched on, the theme, the volume and the tone. The file is saved beside index.html, which is also how settings move between browsers — see Choosing a browser.

    Each file records the version that wrote it and the date and time, to the second, so two of them on a desktop can be told apart. Importing says which version it came from. A file written by an older version is read and brought forward without asking.

    09Recording

    Hold either Shift key and a small red REC button appears beside play. Press it to start, press it again to stop. It stays visible while it is recording whether you are holding Shift or not, and the dot on it blinks so you can see at a glance that it is running. When you stop it, it turns green and reads SAVED for a few seconds before it goes, so you know the file was written.

    The file lands in your Downloads folder, named for when it started and how long it ran:

    DSRadio-260913191404-7.m4a started 2026-09-13 19:14:04, ran 7 s

    It is AAC in an .m4a file, about 96 kbps, which is roughly 45 MB an hour and opens by double-click on Windows, macOS, a phone or a car stereo.

    What is recorded is the broadcast, not what comes out of your speakers. Turning the volume down, or dialling in bass for the room, changes what you hear and not what lands in the file, so a recording made quietly is not a quiet recording.

    Two things it will not do

    A station that cannot drive the meter cannot be recorded either — it is the same permission, and the button says so rather than disappearing.

    Closing the window while it is still recording loses that recording: press stop first.

    10Stream types

    Paste any of these into a station’s stream URL. The radio works out what to do with it.

    MP3 and AAC streams

    The ordinary kind, and what most Icecast and Shoutcast stations hand out. Everything works: sound, the meter, and the tone controls.

    Playlist files (.pls and .m3u)

    Plenty of stations publish one of these as their “Listen” link. It is not a stream; it is a short text file with the real address inside it. The radio reads the file the first time you play that station, keeps the address it finds, and goes straight to it from then on. If the station’s server refuses the request the file cannot be read, and the station will not play; open the file in a text editor and use the address from inside it instead.

    HLS streams (.m3u8)

    These play, but they carry a longer delay by design, and stopping and starting one rewinds you ten to twenty seconds. The player is handed whole pre-recorded chunks and has to begin at the start of the newest one. There is no way around that from here.

    What the radio does fix is the other HLS fault, which sounds worse: a few seconds in, the last several seconds play again. A station like CBC Radio 1 publishes a list of the same programme at several bitrates, twice over, on two different delivery networks. Browsers start on the lowest bitrate and step up once they have measured the connection, and the step up can land on the other network, whose copy is a few seconds behind — so you hear those seconds twice. The radio reads that list itself and hands the browser one entry, the best one, so there is nothing for it to switch to. It also means you get the full bitrate from the first second instead of the tenth.

    If the connection cannot carry that entry, the radio steps down the list a rung at a time as it retries, and goes back to the top once the stream has held for ten seconds.

    .asx and .xspf

    Not handled. They are Windows Media and XML playlist formats. Open one in a text editor and use the stream address inside it.

    Anything else

    If a link will not play, try it in a browser tab on its own. If the tab cannot play it either, neither can the radio.

    A note on joining live

    A station sends a second or so of audio it has already broadcast the moment you connect, so the player has something to start on. The radio skips past it and joins at the live edge, which is why stopping and starting no longer repeats the last second. HLS stations are the exception, for the reason above.

    11Your data

    Everything lives in your browser’s storage on this machine. No account, no sign-in, nothing uploaded, no analytics.

    The page asks Google Fonts for its typefaces each time it opens, which tells Google an anonymous request came from your address, the same as any web page using a hosted font. Playing a station tells that station the same. Nothing else leaves the machine.

    The app checks a single file on GitHub to see whether a newer version has been published — a few seconds after it opens, and every six hours it is left running. A launch that already asked within the last ten minutes does not ask again. When there is one it shows a small Update available pill beside the wordmark and a dot on the Settings control — the same mark in the same place whichever theme you are in. The dot at the head of the pill blinks, lit for three quarters of every two seconds and snapping on before fading off in sixty milliseconds: it is the only thing on the face that moves of its own accord, which is what lets a notice this quiet still be caught out of the corner of the eye. A machine set to reduced motion gets it held lit instead. Both marks are the same alert orange in every theme, deliberately not the cabinet's own colour — news should not be wearing it. It sends nothing about you and downloads nothing; the page installs nothing and cannot. The switch beside it in Settings → Service turns that check off for good.

    The pill carries a small × in a ring. Press it and the pill goes away until the next time the radio has actually been out to look, so it is a snooze rather than a mute. The dot on the Settings control is not touched by it: that one stays for as long as the update is there and has not been installed.

    The shortcut button, and why it disappears

    The small icon in the top bar offers to put a shortcut on the Desktop, and on Windows it now hides itself once there is one. The page cannot see your Desktop — a page opened from a disk cannot see any of that disk — so it is told: the launcher lists the Desktop at every start and writes the answer into assets/shortcut.js, one line of JavaScript, which the page loads the same way it loads a settings seed.

    Anything other than a clear yes leaves the button showing. No file, an unreadable file, an error, or a machine where no launcher runs at all — which is macOS and Linux, where that file is never written and the top bar stays exactly as it always was. Hiding on not knowing would be the one failure worth avoiding: somebody whose shortcut has just gone is the person who needs the button most.

    The same action lives permanently in Settings → Service, and that one never hides. The icon is the convenience; the drawer is the guarantee.

    Keeping up to date

    What the notice means depends on what you are running it on. The updating is done by a Windows batch file, so saying so on a Mac or on Linux would be a promise that cannot be kept; the radio checks and says the right thing for the machine it is on.

    On Windows the notice is news, not an instruction. There is nothing to do with it. Your Desktop shortcut does not point at a browser — it points at Win - Open Deskside Radio.cmd, which opens the radio and then, once a day, asks the same question the app asks. If a newer version has been published it fetches and unpacks it in the background while you listen. The radio is running it the next time you open it, and the readout says which version that is.

    Clicking the notice opens a small dialog rather than a releases page, and what it says depends on something only this machine knows: whether the new version has already been fetched. If it has, it offers to close the radio, because reopening is then the whole of the update. If it has not, it says so, shows the two launches — the next one collects it, the one after runs it — and offers nothing to press but Got it. The page works that out by reading a line the build leaves in the app folder, which is the one thing a page opened from a disk can find out about the disk it was opened from.

    So the notice you see today is acted on at the next launch and visible at the one after: a radio opened daily is current within a day or two, with nobody doing anything. To take one the moment you hear about it instead, run Win-Install-or-Update-Deskside-Radio.cmd in the app folder — it carries no Mark of the Web, so it costs none of the prompts a fresh download does, and holding Shift on Settings → Service gives you a button that opens the folder. Deskside Radio - Update in the Start menu runs the same file, where the installer made one.

    To stop the radio updating itself, run Win - Automatic Updates.cmd off in the app folder; with no argument it starts again. It is a script rather than a switch in Settings for a plain reason: the app's settings live in the browser's own storage, which a batch file cannot read, so the answer is kept where the launcher can see it — one small file in the app folder, the same shape as starting with Windows being one file in the Startup folder. Turning it off does not turn off the notice, which has its own switch.

    On macOS and Linux the notice reads get it from GitHub and takes you to the releases page. Download deskside-radio.zip, unpack it over your app folder, and reopen the radio. There is no installer to run, nothing to uninstall, and nothing that updates itself: the launcher there is a shell script that opens the browser and stops.

    The installer checks for a newer copy of itself before it does anything else, and hands the job over if there is one. It ships inside the zip, so the copy in your app folder is always one release behind the version it is about to install — which would mean a fix to the way installing works could never reach the install that needed it.

    Nothing is installed to make that happen. There is no service, no scheduled task, nothing written to the registry for it, and nothing running when the radio is not — the same promise Win - Start with Windows (On-Off).cmd makes, and it is still kept. The updating is the opener doing one more thing on its way past and then exiting, which is what a scheduled task would have been for, without being one.

    The page itself still installs nothing, and still cannot: a page opened from a disk has no way to run a program, and one that could would be a hole worth more than the convenience. All of the above is the launcher — the script the shortcut actually points at, which already ran at every launch.

    Three things it will not do. It never touches anything outside the folder it was opened from. It checks the archive before it writes a single file, so a truncated download is nothing having happened rather than half an app. And it fails quietly — offline, behind a proxy, read-only folder — and tries again tomorrow, because the radio is already open and playing and an update is never worth interrupting that.

    An update replaces every file in the app folder and loses nothing, because your stations, schedule and settings are not in it — they are in the browser profile. Anything else you left beside index.html, such as a settings seed, survives as well: the update unpacks over the top rather than clearing the folder out first.

    Check now, next to that switch, asks straight away instead of waiting for the day to turn over. It says Up to date when there is nothing new, names the version when there is, and goes quiet while the switch is off.

    12If something goes wrong

    The meter says a stream blocks it
    Some stations refuse the cross-origin access the meter needs. The audio is fine; only the meter and the tone controls are unavailable for that station.
    A station says the stream is gone
    It answered, and there was nothing behind it — the station has retired that stream, which happens more often than you would think. The radio checks each quality of an HLS stream before playing it, and when none of them are there it says so and stops reconnecting rather than trying all night. Press play to make it look again, or replace the URL from Find a station.
    A station shows “Web stream” instead of a frequency
    Its name had no frequency in it, and an internet-only station genuinely has no dial position. If it does broadcast over the air, type the frequency into the station's own field as 99.1 FM or 1010 AM and the dial will point at it.
    Uninstalling left the folder behind
    Fixed in 1.4.3. Before that it removed the app folder but not %LOCALAPPDATA%\DesksideRadio around it, and in 1.4.0 and 1.4.1 it removed nothing at all and said it had. Run the current uninstaller again — everything it does is safe to repeat — or delete that folder by hand, which is all that is left of it.
    Long names are cut off instead of scrolling
    Windows is set to reduce animation — Settings → Accessibility → Visual effects → Animation effects, which is often off on a work machine. That setting turns off every animation in this app, and scrolling is one of them. A name you cannot read is information lost rather than motion saved, so Settings → Theme offers Scroll long names anyway whenever it detects that. Nothing else starts moving.
    The lamp blinks amber and green, and it says no audio
    The stream is connected and arriving, and carrying silence. That is the station's end, not yours — a dead encoder or genuine dead air. The radio re-tunes itself after 10 seconds of it, and again after 30, 90 and 120 seconds, which usually lands on a different server and fixes it. After four goes it stops trying and leaves the lamp saying so, rather than interrupting a station that is simply off the air. It can only notice this where the meter works, so a station that blocks the meter will not be caught.
    A station will not play
    Check the URL plays in a browser tab on its own. Some directory entries are playlist files rather than streams; the finder flags those before you add them.
    Nothing plays until I click
    You opened index.html directly rather than the shortcut. See Why use the shortcut.
    Start again
    Settings → Service → Reset. It clears everything and restores the stations and settings a fresh copy starts with.
